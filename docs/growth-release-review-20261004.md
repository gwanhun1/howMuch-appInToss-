# 경조사 금액 가이드·이름 검색 구현 및 앱인토스 점검

검토일: 2026-10-04 (Asia/Seoul)

## 변경 결과

- 메인에서 ‘얼마 낼까? 상황별 금액 가이드’로 진입한다. 최초 진입에는 입력창이나 동의문을 자동 노출하지 않는다.
- 축의금·조의금·돌잔치, 관계, 친밀도, 참석 여부를 선택한다. 생성형 AI나 외부 통계를 사용하지 않는 자체 참고 규칙이며, 결과에 기준을 고지한다.
- 조의금은 조문 여부로 금액 선택지를 변경하지 않는다.
- 개인의 같은 유형 지출 기록과, 입력한 이름에 일치하는 보낸·받은 기록을 참고한다. 동명이인 가능성을 표시한다.
- 선택 금액·이름·관계를 기존 입력창으로 전달한다. 보낸 마음 초안만 만들며, 사용자가 저장하기 전에는 DB·합계를 변경하지 않는다. 예정 금액은 실제로 보낸 뒤 기록하도록 안내한다.
- 이름 검색은 보낸·받은 모드를 함께 조회하고 이름·관계별로 묶는다. 부분 검색, 공백 제거, 한글 정규화, 날짜순 내역, 각 모드 합계를 지원한다.
- 가이드 이용은 기록 연결과 독립적이다. 연결 중·실패에는 가이드를 이용할 수 있고 기록 입력은 비활성화한다.
- 검색과 가이드는 기존 사용자 기록만 사용하며 새 컬렉션, 사람 식별자, 추가 개인정보, 권한 요청을 만들지 않는다.

### Gate 2 — 정량 기준

- dist 총 크기: 37,192 KiB → 1,668 KiB. SDK 3.x에서 네이티브 번들을 생성하지 않으므로 이 감소를 기능 최적화 성과로 해석하지 않는다.
- 비교 가능한 웹 자산(빌드 로그 합계): 1,650.82 kB → 1,677.30 kB, +1.60%. +10% 이내.
- 새 개발 의존성: @apps-in-toss/devtools 3.7.0. 런타임 라이브러리 신규 추가 없음. 기존 SDK·TDS 버전 변경.
- 10,000개 합성 기록을 이름으로 검색·묶기·정렬: 개발 컴퓨터에서 18 ms. 모바일 실제 성능 측정은 아님.
- 기존 TDS 중심 대형 청크 경고는 남음. 가이드 페이지는 별도 lazy 청크(약 5.18 kB)로 분리.

### Gate 3 — 정성 평가

- 컨벤션 4/5: 가이드 pages → components → hooks → apis의 참고 규칙 경계와 응답 타입을 분리. 검색은 서버 호출 없이 기존 기록을 hook에서 조회. Action: 실제 서버가 필요하지 않은 API 계층은 추가하지 않음.
- 사용자 흐름 4/5: 390px 모바일 폭 브라우저에서 최초 화면, 상황 변경, 금액 선택, 이름 입력, 입력창 전달, 검색 없음과 검색 초기화를 확인. Action: 토스앱에서 중복 내비게이션·시스템 뒤로가기·키보드·재진입을 추가 검증해야 함.
- 상태 관리 4/5: 상황·검색 상태는 로컬 hook, 저장 초안·모드 변경은 Zustand action. Action: 저장 성공·실패 롤백, 취소 시 무저장, 토스 뒤로가기 구독 해제를 자동 테스트로 검증.

### 검증 경계

- 브라우저에서 기록 입력까지 실제 화면을 확인했다. 운영 DB에 합성 기록을 저장하지 않았다.
- 저장 성공→합계→검색 및 실패 롤백은 recordService를 mock한 테스트다. 실제 Firestore 저장·재조회 통합 검증과 동일하지 않다.
- Java Runtime이 없어 Firestore 에뮬레이터는 실행하지 못했다.
- 실제 토스앱 QR 테스트, 콘솔 브랜드·등록 기능 URL·기존 운영 버전 확인, 심사 승인은 완료하지 않았다.

## 출시 전에 해결·확인할 사항

1. **기존 Firestore 소유권 검증**: `firestore.rules`의 `canAccess`는 로그인한 사용자의 UID가 일치하거나 경로가 `key_<64 hex>`이면 접근을 허용한다. 이는 해시 경로를 비밀값처럼 사용하는 구조이고, 인증 사용자와 해당 기록 소유자의 관계를 서버에서 검증하지 않는다. 다른 사용자의 경로가 알려지면 읽기·쓰기 권한이 생길 수 있으므로, 신뢰할 수 있는 서버에서 토스 사용자 식별을 검증하고 Firebase 사용자/클레임과 소유권을 연결하는 개선이 필요하다. 이번 변경에서는 인증·권한·기존 데이터 구조를 수정하지 않았다. 이 항목은 전체 정책 충족을 선언하기 전에 점검해야 한다.
2. **SDK 3.x 실기기 검증**: 기존 기록 유지, 토스 사용자 식별, HTTPS 요청이 새 운영·QR origin에서 동작하는지 확인한다. 필요 시 Firebase 콘솔·서버 origin 설정을 확인한다.
3. **전체 뒤로가기 경로**: 최초 화면 종료, 가이드→메인, 가이드→기록 입력→금액 입력→기록 입력, 프로필·약관 시트의 닫힘을 iOS/Android 토스앱에서 확인한다.
4. **콘솔 브랜드·기능 소개**: SDK 3.x는 브랜드 이름·아이콘을 콘솔에서 관리한다. 콘솔의 실제 등록 정보와 앱 이름을 대조한다. 새 가이드의 별도 기능 URL은 등록하지 않았으며, 현 구현의 진입점은 메인이다.
5. **검수·출시**: SDK 3.x로 공개 출시하면 2.x로 되돌릴 수 없다는 공식 주의사항을 고려해 QR 테스트 후 콘솔 검수를 진행한다.

기능 구현과 로컬 검증은 완료. 앱 전체의 정책 적합성 및 출시 승인은 위 사항 검증 후 판단한다.
