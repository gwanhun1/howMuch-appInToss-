# 성장 기능 디자인 최종 점검

검토일: 2026-10-04 (Asia/Seoul)

## 메인 기능의 우선순위

서비스의 중심은 보낸·받은 경조사금을 귀엽게 기록하고 모아보는 경험이다. 메인 최상단의 큰 기능 버튼 3개를 제거하고 보낸·받은 모드와 합계를 먼저 배치했다. 가이드·예정 비용·축의금 장부는 아래에 작은 TDS weak/dark 버튼으로 배치했다. 기록 카드·추가 카드의 기존 색상·형태·동작을 유지한다. 보조 버튼은 좁은 화면에서 필요하면 줄바꿈한다.

## 시스템 정합성 수정

- 메인·가이드·계산기·장부의 좌우 여백은 20px 기준이다. 서브 화면의 본문 상단은 16px, 헤더는 최소 56px로 통일했다.
- FeatureHeader를 가이드에도 재사용했다. 네이티브 뒤로가기 이벤트와 브라우저 돌아가기 버튼을 유지한다.
- TDS 입력은 자체 좌우 20px 패딩이 있으므로 FeatureTextField 래퍼에서 주변 여백 중복을 상쇄한다. 카드 안쪽 입력이 제목보다 20px 더 들여쓰기되던 문제를 수정했다.
- 입력 라벨을 sustain으로 고정해 빈 입력 상태에서도 이름·예산·금액·관계를 바로 알 수 있게 했다. 접근성 이름도 라벨에 맞췄다.
- 입력 간격은 기존 12·16px, 카드 안쪽은 20px를 사용한다. 큰 카드 모서리는 기존 기록 카드의 24px에 맞추고 검색 결과의 작은 패널은 16px를 유지한다.
- 안내 grey600·강조 blue600·오류 red600·테두리 grey200을 adaptive 토큰으로 맞췄다. 날짜·월·CSV 입력의 고정 흰 배경도 TDS 입력과 같은 adaptiveGreyOpacity50으로 바꿨다.
- 가이드 질문 제목은 16px로 명시해 기본 legend 스타일로 지나치게 커지던 문제를 수정했다. 긴 이름·설명 줄바꿈과 금액 정렬을 정리했다.

## 3-Gate 증거 보고서

### Gate 1 — 필수 기준

- PASS 타입: Node 24 `tsc -b`, 에러 0개.
- PASS 린트: `npm run lint`, 에러 0개.
- PASS 빌드: 웹·SDK 3.x .ait 생성 성공. 마지막 CSS 조정 후 빌드도 재실행했다.
- PASS 신규 any 0개, diff 공백 검사 통과.
- PASS 테스트 49개 통과, 기존 에뮬레이터 테스트 1개 제외.

### Gate 2 — 정량 기준

- dist 1,696 KiB → 1,696 KiB, 표시 단위 기준 증가 0%, 10% 이내.
- 새 의존성 없음. 계산·저장·네트워크 동작 변경 없음. 별도 응답 시간 목표는 정의하지 않았다.

### Gate 3 — 정성 평가

- 컨벤션 4/5. Evidence: 기존 TDS 버튼·TextField·adaptive 색상·20px 간격을 재사용한다. Action: 입력과 헤더의 공통 컴포넌트로 중복 패딩 및 화면별 차이를 제거했다.
- 사용자 흐름 4/5. Evidence: 390px 메인·계산기·가이드 화면을 시각 확인하고, 320px에서 메인·가이드·계산기·장부의 document scrollWidth가 clientWidth와 같음을 확인했다. 보조 메뉴의 각 화면 진입과 뒤로가기를 확인했다. Action: 기록 중심의 메인 우선순위로 버튼 크기와 배치를 수정했다.
- 상태 관리 4/5. Evidence: 기존 hook/store와 저장 동작을 유지한다. Action: 입력 공통화는 표시 props만 변경했으며 기존 테스트를 실행했다.

## 남은 출시 확인

기능 구현과 이번 UI 점검은 완료 범위다. 실제 토스 기기의 네이티브 헤더·키보드·파일 저장·다크모드 확인은 출시 검증에 남아 있다. 이번 색상 점검은 adaptive 토큰 적용 확인이며 실제 다크모드 시각 검증을 완료했다는 의미는 아니다. 기존 Firestore 소유권 문제와 공유 초대 보류도 유지한다. push·배포는 수행하지 않는다.
