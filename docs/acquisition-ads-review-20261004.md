# 앱인토스 광고 유입과 새 노출 정책 — 분석·설정 이력

검토일: 2026-10-04 (Asia/Seoul)

## 결론

사용자의 추가 조건에 따라 광고비 0원·사업자등록 없이 가능한 검색·공유·추천 노출을 목표로 한다. 토스애즈 캠페인·광고계정 생성·포인트 지급 프로모션은 진행하지 않는다. 아래 유료 캠페인 초안은 이전 검토 이력이며 실행 대상에서 제외한다. 이번 결정은 실업급여 수급 가능 여부에 관한 법적 판단이 아니다.

경조사금을 귀엽게 기록하는 메인 기능을 소개하고, 방문 이후 실제 기록 저장과 재방문을 측정한다. 구현한 분석 이벤트는 유료 광고 없이도 추천 노출·이용 흐름 개선에 활용할 수 있으므로 유지한다.

## 무료 유입 운영 방향 (최신)

- 토스 검색: 소개 문구는 ‘보낸·받은 축의금과 경조사금을 귀엽게 기록해요’를 중심으로 작성하고 실제 기능과 일치시킨다. 이름 검색·가이드·계산기는 보조 기능으로 소개한다.
- 공유: 공개 미니앱 메인 링크를 활용한다. 테스트 전용 주소나 개인 경조사 기록·CSV를 유입 소재로 공유하지 않는다. 링크 공유는 현재 기능 범위이며 상대방의 기록에 접근하는 공동 장부와는 다르다.
- 추천 노출: 10월 22일 정책에 맞춰 저장 전환·재방문·리뷰·성능을 개선한다. 추천 선정은 토스 평가에 따르며 비용 0원으로 노출량을 보장하지 않는다.
- 핵심 지표: 기존 7일 재방문은 유지하고, 공개 버전에서 `howmuch_record_saved`가 실제 집계되면 대표 전환을 저장 성공으로 변경한다. 콘솔 선택 목록에 없는 이벤트를 가짜로 만들지 않는다.
- 비용 경계: 여기서 무료는 유입 광고비를 쓰지 않는다는 뜻이다. 기존 Firebase 등 인프라 사용료까지 0원이라고 보장하지 않는다.
- 광고 수익·유료 결제·유료 홍보·포인트 지급 기능은 새로 활성화하지 않는다. 사업자등록을 하지 않았다는 사실만으로 수급에 영향이 없다고 판단하지 않는다.

## 확인한 현재 상태

- 크롬의 로그인된 `howmuchmoney` 콘솔에서 토스앱 광고·핵심 지표·이벤트 메뉴를 확인했다.
- 활성 지표: 7일 이후 재방문 유저. 대표 전환: 유저 식별키 발급받은 유저.
- 대표 전환은 자동 식별키 발급을 측정하므로 핵심 가치인 기록 저장 성과와 다르다.
- 이벤트 목록에는 기본 진입·체류·화면 이벤트가 있지만 기록 저장 성공 이벤트는 없다. 직접 조합 편집의 이벤트 선택 목록은 비어 있어 새 조건을 저장하지 않았다. 원래 지표를 유지하고 편집을 종료했다.
- 홈 대시보드 선택 구간은 2026-09-04~2026-10-04이며 표시된 유저 집계는 22명이다. 이 값은 하루 DAU가 아니라 선택 구간 표시 값이며, 작은 표본을 근거로 성별·OS 타겟을 제한하지 않는다.
- 토스애즈 연결 화면에는 비즈니스 그룹·광고계정의 생성 또는 참여가 필요하다고 나온다. 해당 단계 진입 후 사업자등록번호 입력 화면을 확인했다. 사업자 정보 입력·그룹 생성·약관 동의·광고계정 생성은 수행하지 않았다.
- 캠페인·소재를 토스애즈에 저장하거나 심사 요청·충전·집행을 실행하지 않았다.

## 적용한 분석 코드

- SDK 3.7.0의 `Analytics.log`를 사용한다. 일반 브라우저에서는 호출하지 않으며 샌드박스는 SDK의 테스트 처리에 따른다.
- `howmuch_record_saved`: 서버 저장 성공 후 실행한다. 고정된 `method=single` 또는 `wedding_ledger`만 전달한다. 일괄 저장은 하객 수만큼이 아니라 저장 작업당 한 번 기록한다.
- 이미 store에 반영된 같은 ID의 일괄 재시도와 기존 기록 수정은 새 기록 전환으로 보내지 않는다.
- `howmuch_tool_opened`: 메인 보조 도구 선택을 기록한다. 고정된 도구 이름만 전달한다.
- 이름·금액·날짜·관계·CSV·Firestore 경로·문서 ID를 분석 payload에 넣지 않는다. SDK가 자동으로 처리하는 미니앱 익명 식별키에 관한 안내는 앱 개인정보처리방침에 추가했다.
- 분석 요청을 기다리느라 저장 완료 UI를 지연시키지 않고, 분석 실패를 저장 실패로 처리하지 않는다. 이벤트는 best-effort이며 완전한 과금 귀속이나 서버 측 정확한 전환 장부를 보장하지 않는다.
- 이 코드만으로 토스애즈 캠페인의 저장당 비용이 자동 계산되는 것은 아니다. 광고계정에서 지원하는 캠페인 전환 연동을 별도로 확인해야 한다. [토스애즈 성과 측정 연동](https://toss-ads.gitbook.io/guide/tracking/integration)

## 메인 기능 중심 광고 문구

콘솔 앱 이름인 ‘얼마냈지’를 브랜드명으로 사용한다. 문구는 신규 기능 출시 여부에 의존하지 않는 기존 기록 기능을 설명한다. 이미지 소재의 주요 문구는 최대 28자·행당 14자, 보조 문구는 최대 18자 기준에 맞춘 초안이다. 광고 소재의 최종 UI 글자수 검사를 거쳐야 한다. [이미지 소재 규격](https://toss-ads.gitbook.io/guide/a-d/creative-guidelines/image)

| 버전 | 주요 문구 (줄바꿈 기준) | 보조 문구 | CTA 후보 |
| --- | --- | --- | --- |
| A | 보낸 마음, 받은 마음을<br>기록해요 | 경조사금을 귀엽게 모아봐요 | 앱 열기 |

처음에는 A·B 두 소재만 비교한다. 클릭률만 높고 기록을 남기지 않는 소재는 축소한다. 광고 수익·첫 저장당 획득 비용·장기 재방문 성과는 현재 데이터로 계산할 수 없으므로 수익성이나 유입 증가를 보장하지 않는다.

## 소재·랜딩 정책 반영

- 실제 제공하는 기록 기능만 소구하고 ‘토스 공식’, ‘축의금 평균 정답’, ‘돈 지급’, ‘미수금 회수’, ‘누구나 절약 보장’ 같은 오해 가능한 문구를 사용하지 않는다.
- 송금 알림·입금 완료·미확인 내역처럼 토스 시스템 메시지로 보이는 광고를 만들지 않는다. 광고 이미지에 토스 로고·알림 UI·토스 화면 캡처를 쓰지 않는다.
- 실제 사용자 기록이나 지폐 도안을 소재로 쓰지 않는다. 자체 브랜드와 단순한 편지·노트 일러스트 방향을 권장한다. 토스 서비스로 혼동될 수 있는 브랜드 표현을 피한다.
- 과장된 숫자·근거 없는 순위·과도한 특수문자를 제외하고 광고와 랜딩의 기능 설명을 일치시킨다.
- 랜딩은 정상 작동하는 모바일 화면이어야 하며 뒤로가기와 문의처가 필요하다. 앱 안에 공개할 문의 이메일·문의 페이지는 사용자에게 요청했으나 아직 제공되지 않아 추가하지 않았다.
- 이번 검토는 설정안의 정책 반영이며 광고 심사 승인이나 서비스 전체 법적 적합성 판정이 아니다. [공통 심사 정책](https://toss-ads.gitbook.io/guide/review/basicguide), [소재·랜딩 심사 정책](https://toss-ads.gitbook.io/guide/review/creativeguide)

## 외부 설정과 전달물

토스애즈 계정 준비와 유료 캠페인은 진행 대상에서 제외했다. 공개 후 이벤트 선택·대표 전환 저장은 무료 유입 운영에서도 필요하다. 앞서 확인한 Firestore 소유권 검증 문제도 출시 전 해결 대상으로 유지한다. 분석이 포함된 새 `howmuchmoney.ait`를 로컬에서 생성했지만 사용자가 테스트하고 업로드하겠다는 요청에 따라 추가 업로드·심사·공개 출시를 실행하지 않았다. 이전 업로드 테스트 주소에는 이번 분석 코드가 들어 있지 않다.

이번 무료 유입 방향 수정은 문서 변경만 포함한다. 기존 타입·린트·빌드·55개 테스트 결과와 번들 크기는 그대로이며 `git diff --check`를 수행한다.
