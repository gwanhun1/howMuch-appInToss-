# 모바일 스크롤 점검 및 확장 전략

2026-10-05. 로컬 수정·검증만 진행했다. 업로드·출시·광고·푸시 캠페인 설정은 하지 않았다.

## 수정 결과

- 기록 카드는 폭과 관계없이 한 줄 3개다. 그리드 트랙을 `minmax(0, 1fr)`로 바꾸고 자식의 최소 폭을 해제했다. 320px에서 긴 이름·1억 원 기록으로 재현한 실제 문서 폭 594px이 320px로 줄었다.
- 360px 미만에서는 카드 내부 패딩과 아바타를 줄인다. 이름은 말줄임하며 전체 이름은 기록을 열어 확인한다. 금액은 화면 폭·자릿수에 맞춰 크기를 조절하고 전체 숫자를 유지한다. 디데이는 한 줄로 표시한다.
- 보낸/받은 전환과 합계는 필요한 경우 줄바꿈한다. 메인 기록 목록 위에는 큰 고정 영역을 추가하지 않는다.
- 최근 세 페이지(금액 가이드·경조사비 계산기·결혼식 빠른 장부)는 좌우 20px, 카드 패딩 20px, 모서리 24px, 기존 TDS/adaptive 색상 기준을 유지한다. 본문은 문서의 세로 스크롤 하나를 사용한다.
- 세 페이지의 제목·돌아가기는 상단 sticky다. 가이드 적용/기록 입력과 장부 저장은 하단 fixed다. ResizeObserver로 버튼 영역 높이를 측정해 줄바꿈·safe area에 따라 본문 공간을 확보한다. 계산기는 즉시 계산하므로 하단 고정 버튼을 추가하지 않는다.
- 긴 목록·이름·합계·버튼은 줄바꿈한다. 날짜·월 입력의 폭과 textarea 크기 변경 방향을 제한한다. 가로 넘침을 단순히 숨기는 대신 내용 자체가 화면 안에 들어오게 한다.
- 금액 입력의 빠른 선택은 가로 스크롤 대신 3열 2행이다. 제목과 확인 버튼을 두고 가운데 본문만 세로 스크롤한다. TDS FixedBottomCTA의 공간 예약을 활용한다.
- 기록 입력·프로필 선택은 TDS BottomSheet의 본문 스크롤 하나만 사용한다. 제목과 저장/취소는 TDS header/cta로 분리했다. 기존 고정 본문 높이와 내부 overflow를 제거했다. 기록 입력에는 TDS 키보드 대응 옵션을 지정했다.
- 화면별 문서 스크롤을 기억한다. 새 화면은 위에서 시작하고 돌아오면 이전 위치를 복원한다. 추가 정보 펼치기의 자동 스크롤은 실제 TDS 스크롤 영역을 따라간다.

## 검증 기록

개인 데이터 저장 없이 로컬 테스트 화면에 12개 기록을 넣었다. 이름은 `긴이름레이아웃확인테스트사람`, 각 금액은 100,000,000원, 날짜는 2030-12-31, 즐겨찾기와 디데이를 함께 표시했다. 계산기 합계는 스트레스 표시값 50억 원, 장부 합계는 12억 원이다. 검증용 파일은 작업 후 삭제했다.

| 화면 | 폭(px) | 확인 결과 |
| --- | --- | --- |
| 3열 기록 카드 | 320, 360, 390, 430 | 문서 폭 = 화면 폭, 가로 넘침 0 |
| 금액 가이드 | 320, 360, 390, 430 | 문서 폭 = 화면 폭, 가로 넘침 0 |
| 경조사비 계산기 | 320, 360, 390, 430 | 문서 폭 = 화면 폭, 가로 넘침 0 |
| 결혼식 빠른 장부 | 320, 360, 390, 430 | 문서 폭 = 화면 폭, 가로 넘침 0 |
| 금액 입력 | 320, 360, 390, 430 | 가로 넘침 0, 본문만 세로 스크롤 |
| 장부 저장 내역·CSV 펼침 | 320 | 긴 이름·금액·파일 입력·textarea 넘침 0 |
| 기록 입력·프로필 선택 | 320 × 400 | 가로 넘침 0, 세로 스크롤 영역 1개, 제목·CTA 표시 |

320px에서 세 보조 페이지 끝까지 스크롤해 sticky 제목을 확인했다. 가이드는 높이 640px/400px에서 하단 버튼 위치를 확인했다. 장부 CSV 펼침의 마지막 입력과 안내가 하단 CTA 위에 나타나는 것을 시각 확인했다. 화면 전환 시 위치 복원 및 버튼 높이 변경에 따른 예약 공간 갱신은 별도 테스트로 검증했다.

실제 토스 iOS/Android 키보드, OS 글자 확대, 다크모드, 기기 safe area는 이번 Chrome 점검으로 검증했다고 볼 수 없다. 400px 높이는 작은 표시 영역 점검이며 실제 키보드 테스트가 아니다. 데이터 저장·삭제·CSV 다운로드는 이 디자인 점검에서 실행하지 않았다.

## 기능 전략

메인 가치는 보낸·받은 마음을 귀엽게 저장하고 나중에 찾는 경험이다. 이미 금액 가이드·예산 계산기·장부·사람 검색이 있으므로 보조 페이지 수보다 기록의 반복 사용성을 우선한다. 아래는 제안이며 새 기능 구현 완료를 의미하지 않는다.

| 순서 | 제안 | 구체적인 사용 경험 | 기대 효과·검증 기준 |
| --- | --- | --- | --- |
| 1 | 지난 기록으로 다시 입력 | 기록 상세의 작은 버튼으로 이름·관계·프로필·종류를 복사해 새 입력을 연다. 날짜·금액을 확인하고 저장하며 기존 기록을 수정하지 않는다. | 재입력 부담 감소. 다시 입력 시작→저장 완료율, 두 번째 기록 완료율 |
| 2 | 앱 소개 공유 | 서비스 메뉴의 작은 공유 버튼. 귀여운 샘플 카드와 앱 소개만 공유하고 실제 이름·금액·기록 ID를 링크에 넣지 않는다. | 신규 유입. 공유 경로 방문→첫 저장 비율. 공유 버튼 클릭을 실제 공유 완료로 집계하지 않음 |
| 3 | 월별 마음 모아보기 | 기존 기록 목록 위 작은 월 선택과 월 합계. 미래 예산과 실제 기록을 구분하고 빈 달을 설명한다. 기본 카드 3열은 유지한다. | 이전 기록 조회·재방문 증가. 월 선택 후 기록 조회율, 30일 재방문 |
| 4 | 작성 중 입력 복원 | 장부와 예산의 작성 중 값을 본인 기기에 보존해 종료·뒤로가기 후 복원. 복원 여부와 삭제 동작을 제공한다. | 입력 중 이탈 후 복귀율. 저장 성공 뒤 임시값 제거와 타 사용자 데이터 분리 필요 |
| 5 | 적절한 리뷰 요청 | 반복 사용 후 저장 성공·완료 안내 뒤 한 번 요청한다. 미노출·실패가 기록 흐름을 막지 않는다. | 서비스 품질 피드백 확보. 같은 세션 반복 요청 금지 |

사람별 기록은 기존 검색을 먼저 활용한다. 동명이인을 자동으로 한 사람으로 합치지 않는다. 공동 장부·연락처 가져오기·무단 자동 알림은 식별·권한·소유권 설계가 필요하므로 우선순위를 낮춘다.

## 무료 유입 방향과 공식 근거

새 사용자 유입 수단이 전혀 없다는 이전 설명은 정정한다. 공식 [노출 가이드](https://developers-apps-in-toss.toss.im/guide/exposure)는 10월 22일부터 변경되는 정책을 안내하며, 검색·공유 링크와 추천 미니앱 노출을 설명한다. 추천 기준은 UX·실사용 지표·리뷰·성능이다. 선정이나 유입 규모를 보장하지는 않는다.

[핵심 지표 가이드](https://developers-apps-in-toss.toss.im/guide/analytics/conversion-metrics)는 활성·전환 지표를 비슷한 사용자에게 노출하고 추천하는 기준으로 사용한다고 명시한다. 이 서비스의 대표 전환 후보는 저장 성공 후 발생하는 기존 `howmuch_record_saved` 이벤트다. 단순 버튼 클릭·도구 진입을 대표 전환으로 두지 않는다. 활성 기준은 경조사 기록의 낮은 사용 빈도를 고려해 30일 내 재방문으로 시작하는 방안을 검토한다. 최종 조건은 콘솔이 제공하는 템플릿·조합과 실제 이벤트 수집을 확인해 정한다. 로컬에 준비된 이벤트 코드가 출시 버전에서 수집되고 있다는 의미는 아니다.

[미니앱 공유 링크](https://developers-apps-in-toss.toss.im/documentation/common/growth/share/miniapp-share-link)는 공유받은 사람이 토스의 지정 화면으로 들어올 수 있게 한다. 보상 없는 앱 소개 공유를 설계할 수 있다. [리뷰 요청](https://developers-apps-in-toss.toss.im/documentation/common/growth/review)은 가치 체감 후 요청하고 요청 미노출이 정상 흐름을 막지 않게 하도록 안내한다.

이번 제안은 광고 수익·결제·유료 광고·보상 프로모션을 도입하지 않는 범위다. 콘솔 설정·외부 발송·업로드는 수행하지 않았다.

## 3-Gate 증거 보고서

### Gate 1 — 필수 기준

- PASS: Node 24 `tsc -b`, 린트 오류 0개, 웹 및 .ait 로컬 빌드 성공.
- PASS: 테스트 58개 통과. 기존 Firestore 에뮬레이터 통합 테스트 1개는 환경 미실행으로 제외.
- PASS: diff 공백 오류와 신규 `any` 없음. 새 의존성 없음.

### Gate 2 — 정량 기준

- `du -sk dist`: 1,700 → 1,712 KiB, 약 +0.71%로 증가 한도 10% 이내.
- 카드 스트레스 화면 문서 폭: 594 → 320px. 5화면 × 4폭, 총 20조건에서 가로 넘침 0.
- 320 × 400 입력창: 외부/내부 2개 스크롤 영역 → TDS 본문 1개.
- 빌드의 큰 청크 및 SDK 정적/동적 import 경고는 남아 있다. 이번 변경의 빌드 실패는 아니다.

### Gate 3 — 정성 평가

- 컨벤션 4/5. Evidence: TDS header/cta, adaptive 색상, 20px 패딩과 24px 카드 모서리 유지. Action: 고정 버튼을 공통 컴포넌트로 묶었다.
- 사용자 흐름 4/5. Evidence: 카드·최근 세 페이지 폭 검사 및 끝부분 시각 확인, 짧은 높이에서 버튼 표시. Action: 본문 스크롤 소유자를 하나로 정리하고 화면별 위치 복원 테스트를 추가했다.
- 상태 관리 4/5. Evidence: 저장·삭제 API 변경 없이 기존 테스트 통과. Action: 레이아웃 측정 관찰자는 종료 시 해제하며 화면 전환 스크롤 구독도 정리한다.

실제 토스 기기의 키보드·다크모드·safe area 검증은 위의 한계대로 남아 있다. 로컬 산출물 생성만 수행했으며 배포 CLI·콘솔 업로드·검토 요청은 실행하지 않았다. 생성된 추적 대상 .ait 파일은 기존 버전으로 되돌려 커밋에서 제외한다.
