# 앱인토스 재심사 및 초기 연결 오류 검증

## 제출 대상

- 앱: 얼마냈지 (`howmuchmoney`), SDK 2.4.7
- 최종 deploymentId: `01a07a5d-5429-787d-940d-0cca4bf32b52`
- 번들: `howmuchmoney.ait`
- `20260907-9`는 초기 연결 오류 제보가 있어 재심사 대상으로 사용하지 않는다.
- 현재 공개 버전은 `20260617-1`. 새 번들 업로드는 공개 출시가 아니다.

## 원인과 수정

1. 최초 실행 50ms 후 가이드를 자동으로 표시하던 코드를 제거했다. 사용자가 ‘사용법 보기’를 누른 경우에만 안내한다. 이전 저장값의 폼·페이지 상태도 복원하지 않는다.
2. 모든 Firebase 요청을 3초 후 실패시키던 타이머가 느린 초기 연결까지 오류로 처리했다. 읽기·인증은 15초, 토스 식별자 확인은 8초까지 기다리며 완료된 타이머는 해제한다.
3. 일회성 조회에 사용하던 Firestore WebChannel 연결을 공식 Firestore Lite의 HTTPS REST로 바꿨다. 실시간 구독과 오프라인 쓰기는 기존 앱에서 사용하지 않았다.
4. 초기화 및 익명 인증 중복 실행을 방지했다. 5초가 지나면 메인 화면 안에서 지연을 안내하고, 실패 시 단계별 사유와 재시도 버튼을 제공한다. 연결 중/실패 상태에서는 기록 변경을 막는다.
5. 토스 식별키 조회 실패를 새 로컬 익명 계정으로 전환하지 않는다. 기존 계정의 기록을 계속 조회할 수 있도록 재시도를 안내한다.
6. 쓰기 요청은 타이머만으로 실패했다고 처리하지 않고 SDK의 실제 결과를 기다린다. 기존 레거시 변환 후 기록 목록을 다시 조회한다.
7. 금액 입력 화면에서 토스 네이티브 뒤로가기를 연결하고, 자체 뒤로가기 아이콘 대신 ‘입력 취소’를 제공한다. 브리지가 없는 브라우저에서도 화면이 깨지지 않도록 처리했다.

## 운영 서버 확인

운영 프로젝트에 임시 인증 계정으로 접속해 빈 테스트 경로만 조회했다. 사용자 기록은 읽거나 수정하지 않았고 임시 인증 계정은 삭제했다.

| 단계 | 결과 | 응답 시간 |
|---|---|---:|
| 익명 인증 | 성공 | 1,271ms |
| 본인 사용자 문서 조회 | 성공, 문서 없음 | 311ms |
| 새 안정 식별자 경로 조회 | 성공, 문서 없음 | 74ms |
| 기록 목록 조회 | 성공, 빈 목록 | 139ms |
| 테스트 인증 계정 정리 | 성공 | 466ms |

운영 DB는 서울 리전 `asia-northeast3`의 Firestore Native로 확인했다. PC 브라우저에서 기존 번들과 수정 번들 모두 운영 DB에 연결해 메인 화면 진입에 성공했다. 이는 측정 시점의 서버 가용성을 확인한 결과이며, 사용자 휴대폰의 토스 웹뷰 연결 성공을 증명하지는 않는다. 웹뷰 지속 연결 지연은 추정 원인으로, 새 QR 실기기 테스트가 필요하다.

## 증거 보고서

### Gate 1 — 필수 기준

- PASS: `npx tsc -b` 및 프로덕션 빌드 타입 검사, 오류 0개.
- PASS: `npm run lint`, 오류 0개.
- PASS: `npm run build`, iOS/Android용 `.ait` 생성 성공.
- PASS: 신규 `any` 없음, `git diff --check` 통과.
- PASS: `HOWMUCH_EMULATOR_TEST=true npm test`, 8개 파일 27개 테스트 통과. 기본 `npm test`는 로컬 에뮬레이터 통합 테스트 1개를 건너뛴다.

테스트 범위: 신규/재진입 시 자동 가이드 미노출, 과거 시트 상태 복원 방지, 사용법 시작/종료, 네이티브 뒤로가기 구독/해제와 브리지 실패, 3초를 초과한 정상 응답, 단계별 시간 초과, 중복 초기화 방지, 느린 응답의 정상 반영, 실패 후 재시도, 토스 식별키 지연 시 계정 보존, Firebase Lite 인증 및 기록 CRUD·합계.

### Gate 2 — 정량 기준

- 최종 `.ait`: 4,215,901바이트. 직전 업로드 4,265,364바이트 대비 약 1.16% 감소.
- 압축 해제한 실제 번들 엔트리 합계: 23,371,134바이트. 앱인토스의 100MB 제한 이내.
- 데이터 서비스 JS: 468.51kB → 289.34kB, 약 38% 감소. gzip 110.83kB → 62.99kB.
- 초기 바텀시트 수정 시 개발용 `@testing-library/react`, `jsdom` 추가. 연결 수정에는 신규 의존성 없음.
- 빌드의 500kB 초과 청크 경고는 TDS가 포함된 기존 AppBootstrap 청크에 남아 있다.
- 실제 토스앱 첫 진입 20초 이내 여부는 새 QR 테스트 전까지 미검증이다.

### Gate 3 — 정성 평가

- 컨벤션 4/5: API·스토어·연결 안내 컴포넌트·타임아웃 유틸을 분리했다. 기존 파일 배치를 유지했다.
- 사용자 흐름 4/5: 첫 진입을 막지 않고 지연/오류/재시도를 메인에서 안내한다. 로컬 브라우저에서 저장·재진입·금액 취소·키보드 가이드 종료를 확인했다. 실기기 검증이 남아 있다.
- 상태 관리 4/5: 초기화는 하나의 진행 중 Promise를 공유하며 성공 데이터를 함께 반영한다. 안내는 로컬 상태, 데이터는 기존 Zustand에 유지한다.

## 재심사 출시 노트

미니앱 최초 진입과 재진입 시 바텀시트 및 기능 안내가 자동으로 열리지 않도록 수정했습니다. 사용법 안내는 하단 ‘사용법 보기’, 기록 입력창은 ‘기록 추가’ 또는 경조사 기록하기를 선택한 경우에만 표시됩니다. 이전 실행의 열린 입력창 상태도 복원하지 않습니다.

초기 데이터 연결은 일회성 HTTPS 요청으로 변경했고, 느린 정상 응답을 3초 만에 실패 처리하던 문제와 중복 초기화를 수정했습니다. 연결이 늦으면 메인 화면 안에서 진행 상태를 안내하며 재시도할 수 있습니다. 토스 사용자 확인 지연 시 다른 익명 계정으로 전환하지 않습니다.

## 남은 출시 절차

1. 새 버전의 QR을 실제 토스앱에서 실행한다.
2. 첫 화면이 20초 이내에 열리고 팝업이 자동으로 나타나지 않는지 확인한다.
3. 기록 추가·저장·재진입 및 금액 입력의 토스 뒤로가기를 확인한다.
4. 오류가 있다면 화면에 표시된 단계별 메시지와 해당 버전을 확인한다.
5. 정상 테스트 후 콘솔 ‘검토 요청’에 위 출시 노트를 입력해 제출한다.
6. 토스 심사 승인 후 ‘출시하기’를 진행한다. 승인과 공개 출시는 아직 완료된 것으로 보고하지 않는다.
