# 마음 마을 구현 및 검증

2026-10-05 (Asia/Seoul)

## 구현 범위

메인의 작은 도구 버튼에서 마음 마을을 연다. 기존 기록 속 캐릭터가 작은 집에 사는 지도다. 집은 3열이며 구역당 최대 6개를 표시한다. 구역 이동 버튼을 사용하므로 가로 스크롤이나 마을 드래그를 요구하지 않는다. 이름·관계순으로 정렬하고 금액·기록 횟수로 집 크기나 이웃의 순위를 바꾸지 않는다.

집을 누르면 TDS BottomSheet에서 이름·관계, 보낸/받은 합계, 날짜순 기록을 확인한다. 기록을 누르면 해당 기록의 보낸/받은 모드로 이동해 기존 수정창을 연다. 저장·삭제는 기존 기능에서 사용자가 실행한다. 빈 마을의 첫 마음 기록하기도 기존 새 기록 입력창으로 연결된다.

하늘집·꽃집·숲집 3종과 곰·쿼카·고양이·펭귄·강아지·돼지 캐릭터 6종으로 꾸밀 수 있다. 기존 프로필 아이콘은 지원 목록 내에서 기본 모습으로 재사용한다. 기본 모습으로 버튼은 선택한 집의 꾸미기만 초기화한다. 꾸미기 데이터는 버전이 있는 사용자별 기기 설정에 집 종류·아이콘·기록 ID만 저장하며 이름·금액·전체 기록은 추가 저장하지 않는다. 저장 차단 시 현재 화면의 변경을 유지하고 기기에 보존되지 않았음을 안내한다.

동일한 이름·관계의 기록을 같은 집에 묶는 표시 기능이다. 사람의 신원을 판별하지 않으며 동명이인 가능성을 안내한다. 가장 먼저 만들어진 기록 ID를 꾸미기 키로 사용한다. 최초 기록을 삭제하거나 기록의 이름·관계를 바꾸면 집 묶음과 꾸미기 연결이 달라질 수 있다. 꾸미기는 기기를 바꾸면 동기화되지 않는다.

## 구조 및 기존 시스템

- pages/HeartVillagePage → components/heart-village → hooks/useHeartVillage → apis/heartVillage 4계층이다.
- 기존 Zustand의 기록을 읽고 별도 Firestore 요청·스키마·권한·인증 수정은 없다.
- 마을은 lazy 로딩으로 진입할 때 코드와 스타일을 내려받는다.
- 20px 본문 여백, 24px 모서리, TDS 버튼·제목·BottomSheet와 adaptive 본문 색상을 재사용한다. 마을 일러스트는 별도의 작은 파스텔 집·하늘·잔디 색을 사용한다.
- 제목은 sticky다. 마을 본문은 문서 스크롤, 상세는 TDS 본문 스크롤만 사용한다. 닫기 버튼은 상세 헤더에 남고 토스 뒤로가기는 집 상세를 먼저 닫는다.
- 작은 화면에서 이름·관계는 말줄임하지만 집 버튼의 접근성 이름과 상세에서 전체 값을 확인한다. 키보드 버튼 조작·선택 상태·구역 안내를 제공한다. 장식은 접근성 트리에서 제외하고 모션 감소 설정을 존중한다.
- 기존 고정 이벤트인 도구 진입 분석에 heart_village 값을 추가했다. 이름·금액·관계·기록 ID를 분석으로 전송하지 않는다.
- 광고·결제·금전 보상·공개 공유·자동 알림은 추가하지 않았다.

## 확인한 사용자 흐름

실제 로컬 앱의 빈 마을에서 첫 마음 기록하기 → 기존 입력창을 확인했다. 개인 데이터 저장 없이 테스트 화면에 긴 이름·관계 및 1억 원 금액 9개 기록을 넣어 8집을 구성했다. 같은 이름·관계의 보낸/받은 기록은 하나의 집으로 모였다.

- 320·360·390·430px에서 지도와 집 상세의 문서 폭이 화면 폭과 같다. 가로 넘침 0개.
- 지도는 첫 구역 3열 6집, 두 번째 구역 2집이며 이전/다음 이동을 확인했다.
- 꽃집·펭귄 변경 → 새로고침 → 마을 재진입 후 복원되는 것을 시각 확인했다.
- 320 × 400px 상세에도 닫기 헤더가 남고 본문 스크롤 영역은 하나다.
- 상세의 받은 마음 기록을 눌러 해당 이름·금액의 기존 수정창이 열리는 것을 확인했다. 저장·삭제는 실행하지 않았다.
- 테스트용 파일은 검증 뒤 제거했다. 광고·Firebase 운영 데이터 쓰기·추가 업로드는 수행하지 않았다.

## 3-Gate 증거 보고서

### Gate 1 — 필수 기준

- PASS: Node 24 tsc -b, 린트 오류 0개, 웹 및 앱인토스 로컬 빌드 성공.
- PASS: 테스트 69개 통과. 기존 Firestore 에뮬레이터 통합 테스트 1개 제외.
- PASS: 신규 any 0개, diff 공백 오류 없음.
- 신규 테스트 11개: 관계가 다른 동명이인 분리, 주고받은 합계와 정렬, 원본 불변, 꾸미기 키 유지, 공백·빈 이름, 사용자별 설정, 손상·미지원 설정, 저장 차단, 구역 축소, 재진입 복원·초기화, 사용자 전환, 실패 시 현재 표시 유지.

### Gate 2 — 정량 기준

- dist: 1,712 → 1,732 KiB, 약 +1.17%로 증가 한도 10% 이내.
- 새 의존성 없음. 마을 JS 9.16 kB / gzip 3.74 kB, CSS 5.17 kB / gzip 1.63 kB. 진입 시 로딩한다.
- 지도 렌더링은 구역당 최대 6집이다. 4폭 × 지도/상세, 총 8조건 가로 넘침 0. 짧은 높이에서도 상세 스크롤 소유자 1개.
- 기존 큰 청크 및 SDK 정적/동적 import 빌드 경고는 남아 있다.

### Gate 3 — 정성 평가

- 컨벤션 4/5. Evidence: 4계층, 기존 TDS·adaptive 스타일, MainPage의 lazy 진입 방식. Action: 집 일러스트를 VillageHouse로 분리해 지도와 상세가 같은 모양을 사용한다.
- 사용자 흐름 4/5. Evidence: 로딩·오류·빈 상태, 구역 이동, 꾸미기와 복원, 기존 기록 열기를 브라우저와 테스트로 확인. Action: 상세 닫기를 헤더에 유지하고 네이티브 뒤로가기도 상세부터 닫도록 연결했다.
- 상태 관리 4/5. Evidence: 기존 기록은 읽기 전용, 선택·구역·꾸미기는 지역 hook, 사용자별 저장과 손상된 설정 처리 테스트 통과. Action: 원본 데이터에 꾸미기를 혼합하지 않고 저장 실패를 기록 저장 오류로 취급하지 않는다.

## 디자인 개선 — 2026-10-05

사용자가 기능은 좋지만 CSS의 완성도가 부족하다고 피드백해 마을 일러스트와 표시 스타일을 개선했다.

- 평면 CSS 지붕을 둥근 지붕·옆면·창틀·그림자·화단이 있는 SVG 집으로 교체했다. useId로 각 집의 그라데이션 ID를 분리한다. 기존 TDS 캐릭터를 창문 안에 표시한다.
- 급격히 나뉘는 하늘/잔디 색과 문자 장식(♣·✿)을 제거했다. 부드러운 배경 그라데이션, 곡선 산책길, 작은 벡터 나무와 화단으로 정리했다.
- 집 아래 이름 표찰과 관계 설명을 분리하고 색·크기·간격을 정돈했다. 집과 기록 카드의 3열을 유지한다.
- 상세에 원형 집 미리보기, 집 색을 구분하는 점, 캐릭터 선택 패널, 보낸/받은 합계 2개 패널을 적용했다. 집 종류·선택·저장 데이터는 유지한다.

- 검증용 파일은 제거했다. 기존 API·원본 기록·Firestore·꾸미기 저장 로직은 수정하지 않았다.
