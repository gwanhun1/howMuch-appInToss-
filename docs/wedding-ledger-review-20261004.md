# 결혼식 빠른 장부 — 구현·검증 이력

검토일: 2026-10-04 (Asia/Seoul)

## 적용

- 이름·받은 금액·관계를 최대 25명까지 입력하고 기존 받은 축의금 기록으로 일괄 저장한다. 스키마 변경 없이 같은 날짜의 축의금 기록을 장부로 모은다.
- 일괄 저장과 합계 변경은 하나의 Firestore transaction에서 수행한다. 읽기를 먼저 완료하고 기록·합계를 함께 쓴다. 같은 ID로 재시도하면 합계가 다시 늘어나지 않는다.
- 저장 중 중복 요청을 차단하고 실패하면 입력과 ID를 유지한다. 성공 후에만 store에 기록을 합치고 입력을 비운다.
- 날짜·이름·관계·금액이 같은 기존 기록이나 입력 행은 중복 의심으로 안내하고 명시적 확인 전 저장을 차단한다. 값이 바뀌면 확인을 초기화한다.
- UTF-8 CSV를 파일 선택 또는 붙여넣기로 불러온다. 최대 100KB·25명, 날짜 일치, 금액 범위와 형식을 확인한다. 불러오기만으로 DB에 저장하지 않는다.
- 날짜별 저장된 기록을 CSV로 내보낸다. 이름·금액·관계·날짜 포함을 안내하고 사용자 버튼으로만 실행한다. 따옴표·줄바꿈을 처리하고 스프레드시트 수식으로 해석될 수 있는 값은 방어한다.
- 토스 환경은 공식 File.saveBase64 API와 지원 여부 확인을 사용하고, 일반 브라우저는 파일 다운로드를 사용한다. 미지원 환경은 오류 안내를 제공한다.
- TDS 버튼·입력·확인 체크박스와 토스 뒤로가기 이벤트를 사용한다. 입력은 화면 왕복 중 유지되지만 앱 종료·새로고침 시 사라짐을 안내한다.

## 3-Gate 증거 보고서

### Gate 1 — 필수 기준

- PASS 타입 체크: Node 24에서 `tsc -b`, 에러 0개.
- PASS 린트: `npm run lint`, 에러 0개.
- PASS 빌드: `npm run build`, 웹 번들과 SDK 3.x .ait 생성 성공.
- PASS any 타입: 신규 any 0개. `git diff --check` 통과.
- PASS 테스트: 49개 통과, 기존 에뮬레이터 테스트 1개 제외. CSV 처리·중복·금액·날짜 검증, 일괄 저장 재시도 합계, transaction 읽기/쓰기 순서, 중복 클릭·저장 실패 입력 유지·CSV 확인 흐름을 검증했다.

### Gate 2 — 정량 기준

- 번들 크기: dist 1,676 → 1,696 KiB, +1.19%로 10% 기준 이내.
- 신규 의존성 없음. 기존 대형 공통 번들 경고는 유지됨.
- 입력 25명·CSV 100KB로 로컬 처리 크기를 제한했다. 별도 응답 시간 목표는 정의하지 않았으며, 실제 기기·네트워크 저장 지연은 미측정이다.

### Gate 3 — 정성 평가

- 컨벤션 일치도 4/5. Evidence: pages→components→hooks→apis로 화면·상태·검증을 분리하고 기존 service/store 경로로 저장한다. Action: 기존 기록 스키마와 합계 계산 함수를 재사용했다.
- 사용자 흐름 4/5. Evidence: 브라우저에서 CSV 입력, 중복 확인 전 저장 비활성화·확인 후 활성화, 화면 왕복 입력 유지를 확인했다. 오류·빈 장부·저장 중 상태를 표시한다. Action: 실제 저장은 서비스 mock과 hook 테스트로 검증했으며, 토스앱 QR·키보드·파일 저장 실기기 검증은 출시 전 수행해야 한다.
- 상태 관리 4/5. Evidence: 입력은 MainPage에 연결된 hook, 저장 기록은 Zustand가 관리한다. 저장 실패 시 입력을 보존하고 성공 후에만 반영한다. Action: 이중 요청과 같은 ID 재시도 테스트를 추가했다.

### 인간 개입 필요 여부

출시 위험 있음: 기존 Firestore 규칙은 `key_` 해시 경로와 요청자의 소유권을 충분히 연결하지 않는다. 인증·권한 설계를 수정하기 전 공유 초대 기능과 공개 출시를 진행하지 않았다. 이번 변경은 인증·규칙·스키마·실제 결제에 손대지 않는다. 콘솔 업로드·심사·공개 출시·push를 실행하지 않았다.

## 제한과 정책 검증 범위

- 같은 날의 결혼식을 별도 행사 ID로 구분하지 않는다. 날짜별 받은 축의금 묶음이며 관계 필드로 신랑측·신부측 등을 구분한다.
- 브라우저에서는 실제 사용자 데이터에 테스트 기록을 저장하지 않았다. 실제 Firestore 에뮬레이터 테스트는 Java Runtime 부재로 제외되며, 권한 안전성이나 전체 정책 통과를 보장하는 결과가 아니다.
- 토스 실기기 파일 선택·저장과 네이티브 뒤로가기는 출시 전 확인해야 한다. 사용자 유입·재방문 개선 효과는 출시 후 측정 대상이다.
- SDK API 확인: [File 파일 저장](https://developers-apps-in-toss.toss.im/documentation/common/file-storage/file), [File.saveBase64](https://developers-apps-in-toss.toss.im/documentation/sdk/domains-api/file/file.savebase64).
