# /score [기능 설명]

## 전체 흐름

```
사용자 요구사항 입력
      ↓
[Agent 1] 구현 A 작성
[Agent 2] 구현 B 작성   ← 동시 실행
[Agent 3] 구현 C 작성
      ↓
[Judge Agent] 3개 구현 채점
      ↓
최고 점수 구현 코드에 반영
      ↓
채점 결과 리포트 출력
```

## 구현 에이전트 지시사항 (Agent 1, 2, 3에게 동일하게 전달)

각 에이전트는 다음 제약 조건 하에 **독립적으로** 구현한다:
- CLAUDE.md 와 기존 패턴을 읽고 정확히 따를 것
- 기존 파일을 수정하지 말고, 구현 내용만 텍스트로 반환할 것
- 실제 파일을 쓰지 않고 코드 블록으로만 출력할 것

각 에이전트는 서로 다른 접근 방식을 취한다:
- **Agent 1**: 가장 보수적인 구현 (기존 패턴 최대한 준수)
- **Agent 2**: 성능 최적화 우선 구현
- **Agent 3**: 타입 안전성 및 에러 처리 강화 구현

## Judge 채점 기준 (100점 만점)

| 항목 | 배점 | 세부 기준 |
|---|---|---|
| 컨벤션 준수 | 25점 | CLAUDE.md 패턴 일치, 네이밍, 파일 구조 |
| 타입 안전성 | 20점 | any 사용 금지, 명시적 타입, 제네릭 활용 |
| 에러 처리 | 20점 | 엣지케이스 커버, 적절한 예외 처리 |
| 성능 & 효율성 | 20점 | 불필요한 리렌더링 방지, 상태 최적화 |
| 가독성 | 15점 | 변수명 명확성, 함수 길이, 복잡도 |

## Judge 출력 형식

```
## 채점 결과

### Agent 1 — [접근 방식 한줄 요약]
- 컨벤션: XX/25 — [이유]
- 타입 안전성: XX/20 — [이유]
- 에러 처리: XX/20 — [이유]
- 성능: XX/20 — [이유]
- 가독성: XX/15 — [이유]
- **총점: XX/100**

### Agent 2 — [접근 방식 한줄 요약]
...

### Agent 3 — [접근 방식 한줄 요약]
...

---

## 🏆 채택: Agent N (XX점)
[채택 이유 2-3문장]

[개선 제안 1-2개 — 다른 에이전트의 장점 중 반영할 것]
```

## 채택 후 처리

Judge가 선정한 구현을 실제 파일에 적용한다:
1. 필요한 파일 생성/수정
2. 관련 타입 정의 확인
3. 테스트 추가 (있으면)

## 실행 모드 선택

**기본 (서브에이전트)**: 사용자가 별도 언급 없으면 서브에이전트 3개를 병렬로 띄워 조용히 실행한다. 빠르고 토큰이 적게 든다.

**관전 모드 (에이전트 팀)**: 사용자가 "보면서", "관전", "팀으로", "회의" 등을 언급하면 **에이전트 팀**으로 실행한다:
- 팀원 3명(`impl-conservative`, `impl-performance`, `impl-safety`)을 생성하고 각자 구현하게 한다
- 구현 완료 후 팀원들끼리 서로의 구현을 비판하고 토론하게 한다 (서로 메시지를 보내 상대 구현의 약점을 지적)
- 리더(메인 세션)가 토론 결과를 반영해 최종 채점한다
- tmux 세션 안에서 실행 중이면 팀원별 분할 창이 자동으로 열린다
- 완료 후 반드시 팀을 정리한다 (팀원 종료 → cleanup)

## 사용 예시

```
/score "경조사 카테고리 필터링 기능 추가"
/score "금액 추천 알고리즘 개선" 팀으로 돌려줘. 보면서 할래
/score "유저 통계 차트 추가"
```
